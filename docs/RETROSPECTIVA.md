# Retrospectiva del Proyecto

En este documento se detalla la retrospectiva final del equipo. Se utilizó el formato **Empezar / Dejar / Continuar** para identificar acciones de mejora.

## Análisis de desafíos

- **Gestión del tiempo y alcance:** Fue un desafío constante dimensionar correctamente los tiempos de desarrollo y el tamaño real de las funcionalidades. En varias ocasiones, subestimamos la complejidad de ciertas integraciones (como la IA o la sincronización de estados en el frontend).
- **Uso de Git y GitHub:** Al principio, la curva de aprendizaje para mantener un flujo de trabajo ordenado (ramas, Pull Requests, resolución de conflictos) fue empinada. A medida que avanzamos, entendimos la importancia de los commits atómicos y de no mezclar refactorizaciones con nuevas funcionalidades.
- **Planeamiento y comunicación:** Priorizamos el diálogo constante entre los integrantes para definir el rumbo del proyecto. Aunque nos costó trasladar todas esas ideas a un tablero formal (issues), el planeamiento charlado durante las clases y en el chat de WhatsApp fue clave para alinear al equipo.

## Empezar a hacer

- **Dividir tareas en issues más pequeñas:** Para evitar ramas que duren semanas y commits gigantes.
- **Estimar con horas de complejidad:** En lugar de estimar "en días", estimar cuántas horas de trabajo real requiere cada tarea para ajustar mejor el alcance del sprint.

## Dejar de hacer

- **Dejar los cambios para el final:** Evitar acumular mucha funcionalidad en una sola rama y empujar al final. Hacer integraciones continuas (al menos un push diario como pide la CI).
- **Dejar que el código "funcione" como única meta:** Evitar dejar código que funcione pero no esté refactorizado o testeado por falta de tiempo.

## Continuar haciendo

- **El diálogo técnico constante:** Seguir priorizando las charlas entre los integrantes para resolver bloqueos o plantear soluciones de diseño.
- **La revisión cruzada de código:** Mantener el hábito de revisar los Pull Requests de los compañeros antes de mergear.
- **El enfoque en la experiencia de usuario (UX):** Continuar prestando atención a los estados de carga y los mensajes de error para que la aplicación no se sienta "rota" ante un fallo.
